# Your hands-on checklist / 你需要亲手完成的部分

本项目代码由 AI 辅助实现。面试和论文申请时，区分你提出的研究问题、产品设计、
亲手验证与 AI 辅助开发，不要把未执行的用户研究写成结果。

1. 在电脑上 clone 当前仓库，运行测试，然后启动 `python3 -m reviewflow.web`。
2. 按 README 的模糊提问场景操作一遍，截取澄清、研究状态、证据、决策门、
   下一步问题、人工决策和审计记录。截图不要包含密钥。
3. 对比 `PROP-001` 高影响且有冲突的案例与 `PROP-002` 低影响的案例。
   解释为什么高置信度不能替代人工批准。
4. 打开原始 JSON 来源，检查 EVID → 文档 → section → 原文路径，解释
   “引用存在”与“证据真的支持推断”之间的区别。
5. 运行压缩实验，查看哪条“排除专利”约束消失，理解这是故意简单的基线，
   不能推导出所有大模型都有同样的失误率。
6. 如果希望展示真实 Jev，自己从 TypeSafe 获取凭据并在本机环境变量配置，
   运行后核对界面引擎、返回 model、概率、confidence 和 usage。不要发给别人。
7. 如果希望展示真实生成模型，安装 Ollama 和本地模型，配置模型名，比较
   生成式解释与 extractive fallback。查看 API 失败和引用验证的回退记录。
8. 独立编写新合成案例，先标注 gold evidence，再跑 benchmark。
9. 真实研究人员测试尚未开展。未来招募评审、设计三组对比，收集实际时间、
   质量、覆盖率、信任和 override 数据，再讨论业务价值。

面试介绍：我关注 AI 如何嵌入企业研究决策流程。研究人员从模糊意图出发，
系统帮助澄清、保留约束、检索可追溯证据并提出下一步问题。生成模型解释，
有界模型分类和路由，组织规则规定边界，人类承担最终判断。

理解重点：知识图谱如何帮助发现关联研究；为什么提出建议不等于批准；
为什么 coverage 和 consistency 不等于 correctness；为什么 override 不一定
代表 AI 出错；系统如何保留失败与未解决的问题。
