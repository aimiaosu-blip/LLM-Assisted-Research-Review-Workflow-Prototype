# V4: Business × AI / Human–AI Collaboration & Knowledge Workflow

Core chain: **Knowledge → AI/LLM → Evidence → Human Review → Decision**.
Default execution is deterministic; optional local LLM inference remains opt-in and unvalidated on a live model.

## Executable demonstration

From the repository root, with Python 3.9+ and no paid key:

```bash
python3 -m unittest discover -s tests -v
python3 demo/run_v4.py --out runs/my-v4
python3 -m reviewflow verify --out runs/my-v4
python3 -m reviewflow retest runs/my-v4/regression/retention.json
```

Use a fresh output directory. Open `runs/my-v4/dashboard.html`. Inspect `review.json`, `audit.json`, `metrics.json`, `feedback.json`, `retest.json` and `regression/retention.json`. All demonstration decisions are synthetic. The CLI supports `run`, `decide`, `support`, `final`, `rca`, `promote`, `feedback`, `retest`, `export`, `verify`; use `--help` for each.

The demo approves the limited participant-count disposition through a human override of the baseline's `review` abstention, requests revision of conflicting retention records, validates criteria ambiguity, emits L2 feedback and replays a frozen regression case. A passing conflict case means **the detector correctly continues to flag the unresolved source conflict**, not that the study has become approvable. No policy repair is silently applied.

## Evidence, trace and governance

Two retrieval channels are recorded: lexical top-k plus the structured fact scan. Selected evidence, extractive claims, model draft, recommendation, heuristic confidence, routes and human events are retained. Source hashes and line/row/JSON-path locations are real input coordinates. Structured facts may declare `original_source`, `page`, `section` for manually curated excerpts; these coordinates are input-supplied and not independently validated. Direct PDF/OCR parsing is not implemented; missing page metadata remains null.

Extractive claim consistency verifies identity against selected source text. The optional model draft is treated as one bounded recommendation claim; matching quotes do **not** certify its interpretation. Human `support` events record supported/unsupported/conflict with reviewer and rationale. General claim decomposition and automatic semantic entailment are future work. Recommendation trace links evidence and the conservative rule outcome, but does not prove inferential validity.

All findings require a human; low heuristic confidence, missing/conflicting evidence, high impact, unverified LLM output and inconsistent repeated outputs add explicit routes. `final` accepts only the declared `decision_owner` role, requires a reason and an override reason when differing from the system decision, and preserves accountable owner and decision rights. Unresolved conflicts/missing/blocked cases or unverified claims cannot receive final `approve`: correct the packet and start a new run. `revise` and `reject` are available. Final disposition is immutable within the run; further RCA is allowed. Legacy `decide` operates on recommendation text and is separate from final disposition. No disposition authorizes actual research execution.

Rights are local declarations, not authenticated access control. Hash chaining detects ordinary edits, not malicious rewriting or log truncation. RCA validation is a human attestation, not independent adjudication.

## Metrics: one meaning per metric

| Metric | Numerator / denominator or definition | Action and limitation |
|---|---|---|
| Evidence Coverage | Claims with nonempty resolvable links / all emitted claims | Inspect unlinked claims; not recall of all necessary evidence. Empty claim set = null. |
| Claim–Evidence Consistency | Supported claims / all emitted claims | Unverified/conflict/unsupported count as not supported; extractive identity and human semantic labels are different evidence levels. |
| Recommendation Consistency | Modal successful exact output count / all repeat attempts per criterion | `--repeats 3`; errors reduce score, all errors = 0. Exact wording stability proxy, not semantic quality; rule repeats are trivially deterministic. |
| AI–Human Agreement | Final decisions equal to baseline decision / finalized findings | Default is rule–human agreement; `review` is an abstention, so a human resolution counts as disagreement. Never interpret disagreement as error. |
| Human Override Rate | Final decisions differing from baseline / finalized findings | Includes resolving abstention. No completed decisions = null. |
| Review Lead Time | Mean elapsed seconds from run creation to final event | Includes idle time, not active labor or measured time saved. |
| Reviewer Workload | Pending final dispositions and human event count | Activity proxy only; not a productivity claim. |
| Badcase Rate | Findings with missing/conflict/blocked state, unverified/unsupported claims, override, evaluation conflict or RCA / all findings | Investigation candidates, not validated AI-error rate. |
| Root Cause Distribution | Counts of human-validated diagnoses by category | Multiple diagnoses per finding allowed; denominator is diagnoses. |

No combined score. Denominators are exported. Repeat checks compare the same snapshotted packet and criteria during one run; optional model configuration is fixed. Repeated model outputs are preserved; there is no claim of calibrated confidence or correctness from consistency.

## Root cause → differentiated improvement

RCA requires observed failure, first divergence, root cause, responsible component, corrective action and validation evidence. Supported categories are Retrieval Failure, Evidence Selection Failure, Evidence Interpretation Failure, Reasoning Failure, Criteria/Policy Failure, Unsupported Claim, Legitimate Human-AI Disagreement and Review Criteria Ambiguity. The last two are explicitly not counted as AI errors. Classification is human-entered; category does not prove causality.

`improvement.py` maps them to RAG/knowledge, prompt/strategy, model capability, business process and product interaction remedies. Adapter errors add tools/API schema, error-handling and fallback suggestions. Examples: retain conflict witnesses for selection failures, clarify policy authority for ambiguous criteria, decompose reasoning tasks before considering another model. No fine-tuning or model switching is performed.

- **L0:** local diagnosis report and differentiated actions.
- **L1:** local JSON ticket with owner and acceptance criteria; no Jira/GitHub issue is sent.
- **L2:** non-executable configuration/change proposal with checks; no settings are auto-applied.
- **L3:** candidate repair PR generation is not implemented.

## Evaluate → diagnose → fix → retest

A validated case can be promoted only with frozen input chunks/criterion, explicit expected result, known required evidence IDs (except missing cases), clear diagnosis and validation evidence. Case creation is exclusive to prevent accidental replacement. Human reviewers maintain the collection; automated deduplication, dataset version registry and size control are not implemented.

`retest` reruns the current retrieval/selection/rule code against frozen inputs and checks classification, required evidence retention and extractive consistency. Nonzero exit status gates failure. `tests/test_v4.py` injects a selection defect, verifies the frozen test fails, then restores the correct implementation and verifies it passes. This is a fault-injection demonstration, not a claim that a real operational incident was fixed. The sample criteria ambiguity remains an explicit human follow-up.

Three feedback outputs are represented: regression JSON, component/prompt/tool suggestions, and policy/knowledge revision recommendations. They are reviewable artifacts, not automatically completed fixes.

## Nine platform capabilities and six assets: honest scope

| Capability | Prototype coverage |
|---|---|
| Dataset management | Frozen JSON cases and human-entry gate; no registry/stratified sampling service |
| Executor | CLI baseline, optional local model, regression replay |
| Trace | Stage inputs/evidence/claims, model errors and human event journal |
| Scorers | Narrow explainable proxies; no calibrated LLM judge |
| Reports | HTML + JSON, explicit denominators |
| RCA | Human validated stage/component diagnosis |
| Optimization | L0–L2 local reviewable feedback |
| Feedback production | Frozen case + local ticket + configuration proposal |
| Reflow and gates | CLI nonzero failure and CI unit/regression suite; no live release integration |

Quality assets: case/regression JSON, run trace/audit JSON, category vocabulary, repair suggestions are present. A judge calibration set is **not implemented**; there is no LLM judge to calibrate. They are small local artifacts, not six enterprise asset services.

Offline gates check required evidence and prohibited approval transitions. Production canary, live handoff/clarification/satisfaction signals, real task completion, rollback/degradation orchestration and P0 risk operations are future work. In a research-review study, measure missed critical evidence, unjustified approval, unresolved clarification, reviewer workload and decision completion—not customer-service refunds or complaint handling. Do not infer online quality from a passing offline test suite.
